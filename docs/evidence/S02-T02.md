# S02-T02 — Server-side authentication boundary

Status: IN PROGRESS (provider-credential ready)

Both APIs now expose `GET /api/v1/auth/session` and enforce:

- Bearer tokens are introspected server-side through the plane's Supabase `/auth/v1/user` endpoint.
- Missing provider URL/secret fails closed with `503`; invalid tokens return `401`.
- Authenticated subjects must already exist as an active `private.app_actor`; no automatic role or privilege assignment occurs.
- Corporate and clinical settings, databases, Supabase projects, and secrets remain separate.
- `httpx` is a runtime dependency; tokens and secret keys are never logged or returned.

Verification: Ruff passes for both API packages and `git diff --check` passes. A real-provider smoke test is intentionally deferred until Supabase credentials are supplied.
