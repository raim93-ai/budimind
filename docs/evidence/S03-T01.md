# S03-T01 — governed directory model and operations

Status: COMPLETE

## Scope

Implemented the clinical-only practitioner directory foundation. Profiles, credential evidence/status, services,
publication approvals, and publication state live in the clinical private schema. Profiles are unpublished by default.
Clinical administrators and clinical operations may create profiles, add services, record credential evidence, review
credentials, approve publication, publish, and suspend through the clinical API; all actions are audited. The public
projection exposes only reviewed profile content and active service details. It excludes credential evidence, internal
identifiers from API responses, and unpublished profiles. A profile is not publishable unless it has two approvals and
at least one currently verified credential with current indemnity coverage. The public projection also removes an
expired credential immediately, preventing stale publication leakage.

## Security and privacy checks

- Operations endpoints use the shared deny-by-default policy and allow only `clinic_admin` or `clinical_operations` on
  the clinical plane.
- Existing policy tests cover wrong role, wrong tenant, wrong plane, missing purpose, and missing relationship denials;
  the new test covers the clinical operations allow path.
- SQL uses bound parameters; public reads are bounded (`limit` 1–50, `offset` 0–10,000) and set privacy-safe public
  caching headers.
- No evidence references, private contact details, or assessment/clinical content are selected by public API routes.
- Credentials are checked for status, credential expiry, and indemnity expiry before publication and in the projection.
- Only synthetic data was used.
